# Components - 可复用组件

## 概述
存放可复用的Vue组件，遵循单一职责原则。

## 组件分类

### 通用组件
- 布局组件
- 表单组件
- 数据展示组件
- 反馈组件

### 业务组件
- 角色相关组件
- 装备相关组件
- 副本相关组件

## 组件设计原则

### 单一职责
- 每个组件只做一件事
- 组件名称应该清晰表达其用途
- 避免组件过于复杂

### 可复用性
- 通过props接收数据
- 通过events向父组件通信
- 提供合理的默认值
- 支持插槽(slot)扩展

### 可维护性
- 清晰的组件结构
- 完善的类型定义
- 必要的注释说明
- 合理的样式隔离

## 命名规范
- **文件名**: kebab-case (如: user-card.vue)
- **组件名**: PascalCase (如: UserCard)
- **Props**: camelCase
- **Events**: kebab-case

## 组件模板
```vue
<template>
  <div class="component-name">
    <!-- 组件内容 -->
  </div>
</template>

<script setup lang="ts">
// 导入
import { ref, computed } from 'vue'

// Props定义
interface Props {
  title: string
  count?: number
}

const props = withDefaults(defineProps<Props>(), {
  count: 0
})

// Emits定义
const emit = defineEmits<{
  update: [value: string]
  delete: [id: string]
}>()

// 响应式数据
const localData = ref('')

// 计算属性
const formattedData = computed(() => {
  return props.title.toUpperCase()
})

// 方法
function handleClick() {
  emit('update', localData.value)
}
</script>

<style scoped>
.component-name {
  /* 组件样式 */
}
</style>
```

## Props设计
- 使用TypeScript接口定义
- 提供合理的默认值
- 添加必要的验证
- 清晰的命名和注释

## Events设计
- 使用TypeScript类型定义
- 事件名称使用kebab-case
- 提供清晰的事件说明
- 避免过度的事件发射

## Slots设计
- 提供默认插槽
- 命名插槽要有语义
- 支持作用域插槽
- 提供插槽内容的默认值

## 样式管理
- 使用scoped样式避免冲突
- 可以使用CSS模块
- 支持主题变量
- 响应式设计

## 性能优化
- 合理使用v-if和v-show
- 列表渲染使用key
- 大列表使用虚拟滚动
- 懒加载组件

## 测试
- 为关键组件编写单元测试
- 测试Props验证
- 测试Events触发
- 测试插槽内容

## 扩展指南
创建新组件时：
1. 确定组件职责和复用性
2. 设计Props和Events接口
3. 实现组件逻辑和模板
4. 添加样式和响应式设计
5. 编写使用文档和示例
6. 考虑测试覆盖
